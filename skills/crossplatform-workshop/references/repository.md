# Репозиторий-шаблон

Механика, снятая с `artifacts/workshop`. Каждый пункт проверен запуском.

## Ветки и теги

```
workshop/wN-end   ← финал, выкладывается ПОСЛЕ пары
  wN-cp5 … wN-cp1 ← теги чекпойнтов
main = workshop/wN-start  ← клонирующий получает СТАРТ
```

**`main` указывает на старт, а не на решение.** Это не мелочь: положите финал на ветку по
умолчанию — и половина группы допишет воркшоп за две минуты.

**Именованная ветка старта нужна вдобавок к `main`.** На странице занятия ветки называются
явно (`workshop/wN-start`, `workshop/wN-end`), и это устойчивее к тому, что `main` кто-нибудь
подвинет.

**Каждый узел обязан собираться.** Прогонять все теги, а не только финал:

```bash
for tag in wN-start wN-cp1 wN-cp2 wN-cp3 wN-cp4 wN-cp5 wN-end; do
  git switch -q --detach $tag
  printf "%-9s " "$tag"
  ./gradlew :desktopApp:compileKotlin -q >/dev/null 2>&1 && echo OK || echo FAIL
done
```

Плюс полный прогон трёх таргетов на старте и на финале.

## Догон

```bash
git add -A && git commit -m wip
git switch -c catchup-cp3 wN-cp3
```

**Первая версия этой инструкции была дефектной, и поймал её только прогон на настоящем клоне.**
Если студент стартует через `git checkout <тег>`, он попадает в detached HEAD; его `wip` уходит
в никуда, а Git предупреждает одной строкой, которую на паре никто не читает.

Поэтому в пре-реквизите стоит:

```bash
git clone <url> && cd <проект>
git switch -c feature/lab-N_frame wN-start
```

Проверить на входе, что все стартовали именно так.

Команда догона и номер текущего чекпойнта висят на экране всю пару.

## Что лежит в стартовом состоянии

| Даётся | Зачем |
|---|---|
| Собирающийся скелет на всех таргетах | настройка сборки — не тема воркшопа |
| Предметные данные одним файлом | сеть появляется в следующей вехе, здесь она только мешает |
| Картинки **локально в ресурсах** | Wi-Fi в аудитории — не то, на что стоит закладываться |
| Мелкие готовые компоненты | иначе шаг распухает вдвое |
| Скрипт проверки (паритет локалей и т. п.) | чекпойнт должен проверяться командой, а не глазами |
| Скелет архитектуры целиком | вывести её с нуля за 90 минут нельзя |
| README с пре-реквизитом и командой догона | — |

Плюс удобство, которое экономит минуты на паре: способ проверить вторую локаль **не меняя язык
системы**. У CMP это `./gradlew :desktopApp:run -Plocale=en`.

## Ловушка

**В стартовом состоянии сидит намеренная ошибка, вскрываемая конкретным чекпойнтом.**

На ПЗ1 это зашитый числом цвет в подложке карточки, вскрываемый чекпойнтом про тему. Он
отработал сильнее задуманного: карточка не только осталась светлой — вместе с цветом пропал
контраст текста, потому что поверхность выводит цвет содержимого из своего цвета.

**Второе следствие называть на паре отдельно.** Студент видит «текст пропал», а не «цвет не
переключился», и связать одно с другим сам не сможет.

Ловушка чинится на своём чекпойнте и **в стартовом состоянии остаётся**. Тег чекпойнта — это
уже починенное состояние: тот, кто догоняет, ловушку пропустил, зато у него рабочий код.

Полезно иметь и **обратный пример** — место, где числовой цвет правильный. На ПЗ1 это бейджи
типов: цвет травы — свойство данных, а не оформления, и темы он слушаться не должен. Различать
эти два случая и есть работа над темой.

## Мелочи, которые портят последний шаг

Шаг «коммит и PR» ломается от грязного дерева, поэтому:

- **`.gitattributes`** — иначе `gradlew.bat` уезжает в LF и не запустится у студентов на Windows:

  ```
  * text=auto eol=lf
  *.bat text eol=crlf
  *.jar binary
  *.png binary
  ```

- **`.gitignore` на артефакты сборки.** `kotlin-js-store/` появляется после первой же сборки
  web и оставляет дерево грязным ровно перед коммитом
- **`local.properties` в `.gitignore`**, `gradle-wrapper.jar` — наоборот, в репозитории

## Цена ошибки в раннем шаге

Правка чекпойнта 1 требует пересобрать всю цепочку тегов: коммиты 2–6 переписываются, теги
переставляются, всё прогоняется заново. На ПЗ1 цепочку пересобирали трижды.

Отсюда порядок: **сначала пройти воркшоп целиком, потом писать спецификацию.** Не наоборот.

Если пересобирать всё же приходится, `git rebase --onto` переносит хвост на исправленный
старт, после чего теги переставляются по тексту коммитов:

```bash
git rebase --onto <новый-старт> <старый-старт> <ветка>
for i in 1 2 3 4 5; do
  c=$(git log <ветка> --format='%H %s' | grep "Чекпойнт $i:" | cut -d' ' -f1)
  git tag -f "wN-cp$i" "$c"
done
```
