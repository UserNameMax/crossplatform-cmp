# Сборка вехи курса кроссплатформенной разработки

Метод, снятый со сборки В1 (23.08.2026). Контекст курса, сетка, вехи и адреса —
[crossplatform-course](../crossplatform-course/SKILL.md). Занятия готовятся профильными
скилами: [crossplatform-lecture](../crossplatform-lecture/SKILL.md),
[crossplatform-workshop](../crossplatform-workshop/SKILL.md),
[crossplatform-lab](../crossplatform-lab/SKILL.md). Оси и чек-листы сверки —
[references/checks.md](references/checks.md).

**Зачем скил поверх трёх готовых.** Веха — единица работы, а не четыре независимых занятия.
Всё, что ломается, ломается на стыках: лекция описывала одну модель навигации, воркшоп через
четыре дня показывал другую; конспект обещал критерий, которого в критериях нет; обзорная
страница требовала то, что контракт запретил. Ни одно из этого не видно, пока пишешь отдельное
занятие, и всё видно, когда читаешь четыре страницы подряд.

## Порядок работы

0. **Черновик критериев вехи** из её ядра — до всего остального
1. **Лекция** — `crossplatform-lecture`
2. **Воркшоп** — `crossplatform-workshop`
3. **Лабораторная** — `crossplatform-lab`; там же критерии доводятся до финала по факту
   прохода воркшопа
4. **Сверка** — [references/checks.md](references/checks.md)
5. **Приземлить вынесенное** — всё, что уехало из вехи, получает адрес
6. **Зафиксировать** — Notion, GitHub, скил курса. Веха не закрыта, пока это не сделано

## Почему критерии первыми

Шаг 0 существует потому, что и лекция, и воркшоп ссылаются на критерии по ходу: «в критериях
приёмки это ошибка», «понадобится на ЛР». Без критериев эти ссылки указывают в пустоту, и
пустота заполняется тем, что автор помнит на момент письма.

На В1 критерии писались последними. Итог: конспект пообещал переиспользуемую карточку и смену
ориентации, обзорная страница вехи потребовала избранное и пагинацию — четырёх этих требований
в критериях нет и не будет, они из соседних вех. Всё четыре нашла сверка, но чинить их пришлось
в четырёх разных документах.

Черновик не обязан быть точным: он обязан существовать. Финал — после прохода воркшопа, когда
известно, что реально успевается на паре и что уезжает в лабораторную.

## Согласование со вторым стеком

Веха проходится дважды, разными людьми. **Одинаковыми обязаны быть** критерии приёмки, форма
приложения и инструменты проверки — если скрипт проверки есть только у одной стороны, критерий
односторонний, и это надо назвать вслух.

**Названными вслух обязаны быть и расхождения, и совпадения.** Расхождение: у одного стека
навигация — список объектов в состоянии, у другого маршрут-строка с адресной строкой из
коробки. Совпадение: схема измерения layout, кодогенерация локалей. Курс, где называют только
различия, читается как «везде по-разному», и сравнение теряет смысл.

**Чужие страницы не правим.** Находки по второй стороне идут списком её владельцу — с адресом
и предложением, без редактирования.

## Что вынесено — то приземлено

Каждая веха что-то отдаёт соседям: тему, которую нечем мотивировать здесь, API без работы,
требование без опоры. Шаг 5 проверяет, что у каждого выноса есть адрес.

| Вынесено | Куда | Ядро вехи | Критерии | Страница ЛР |
|---|---|---|---|---|

Пустая клетка — обещание в никуда. На В1 так нашлись четыре: эффекты композиции, `snapshotFlow`,
`derivedStateOf` с `produceState` и `rememberSaveable` — все были «отложены сознательно», и ни
один не был записан в вехе, которая их получила.

## Фиксация

Что коммитится по ходу, знает каждый профильный скил. Веха закрывается проверкой, что результат
лежит в трёх местах и нигде не расходится.

**Notion.** Строка занятия есть для всех четырёх пар, `Готовность` обновлена. Страница каждого
занятия заполнена по шаблону своего скила, подстраницы конспектов на месте. Критерии — в
контракте, страница ЛР ссылается, а не копирует. Ссылки на артефакты ведут на GitHub, а не на
локальный путь. Каждое решение записано **с датой**: через месяц причина по памяти не
восстанавливается. Отменённое вычищено с обзорных страниц.

**GitHub.** Шаблон воркшопа: `main` — старт, теги чекпойнтов на месте и каждый собирается.
Стенд лекции запушен вместе с медиа. Указатель подмодуля в зонтичном репозитории обновлён,
иначе зонтик показывает вчерашнее. README без заглушек: адрес клона настоящий, команды запуска
проверены **из чистого клона**. Секретов в индексе нет. Деревья чистые, и всё **запушено** —
на «закоммичено локально» легко остановиться и счесть сделанным.

**Скил курса.** `crossplatform-course` — память между сессиями: адреса, решения с датой,
закрытые открытые вопросы. Не записанное там выясняется заново. Скилы лежат в репозитории,
поэтому правка метода — тоже коммит.

## Ловушки

Каждая наступлена при сборке В1.

- **Обзорная страница устаревает быстрее занятий.** Решение принимается в одном месте, а живёт
  в четырёх: контракт, ядро вехи, конспект, страница ЛР
- **Правка под новые правила рождает новые дыры.** Переписанная страница установочной потеряла
  выдачу базовой вёрстки, которую обещал конспект лекции
- **Уточнение библиотеки меняет модель.** «Compose Navigation» → Navigation 3 сменило маршрутную
  модель на список объектов и обнулило обоснование парности со вторым стеком. Меняешь
  инструмент — перепроверяй мостик
- **Утверждение из головы.** Четыре ложных за две пары, все поймал запуск. Сюда же — «визард
  делает модуль `composeApp`»: проверяется выводом генератора, а не памятью
- **Сверка по памяти не работает.** Страницы перечитываются подряд, включая подстраницы
  конспектов: половина находок появилась только на втором чтении
- **Правка без согласования.** Сверка находит десятки расхождений; какие из них дефекты, а
  какие сознательный выбор, решает владелец курса
